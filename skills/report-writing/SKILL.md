# 报告章节写作

## 适用范围

仅用于 `document.write_section` 首稿。以当前章节目标、全文大纲、研究摘要、近期已批准章节摘要、写作约束和已回取的 `EvidenceBundle` 为输入，形成可审核的中文分析章节。

`ResearchReport` 的摘要和关键结论用于确定调查方向，不能单独作为事实依据。事实、数据、机构行动、时间判断和可核验的重要结论必须由当前 EvidenceBundle 中的证据支持。

章节修订使用独立的 `report-revision` 指导。搜索、Embedding、Rerank、证据持久化、A2A 状态、文件版本、Token 计算、模型参数和权限由程序及配置管理。

## 写作方法

1. 依据章节目标、证据要求和写作约束确定本章需要回答的核心问题，并形成少量相互衔接的关键主张。保持主题、地区、时间范围和目标读者一致。
2. 为每项关键主张匹配 EvidenceBundle 中的证据。区分直接支持、间接支持、相互冲突和证据不足；优先使用与主张直接相关、定位完整、核验状态较高的材料。来源类型和 Provider 名称本身不等同于事实可信度。
3. 采用结论先行的中文行业分析表达。围绕“现状与事实—形成机制或驱动因素—影响与风险—趋势判断”选择与本章目标相关的层次，不机械套用全部层次。
4. 每段集中表达一个主要观点。综合多个来源形成分析关系，避免逐条复述搜索结果、罗列链接或把摘要拼接成正文。
   当 EvidenceBundle 中存在多份直接相关来源时，优先综合这些来源并在相应主张处引用；不为达到固定数量而引入无关材料。
5. 对事实陈述及可核验的重要判断，在相关句子或段落后使用上下文分配的读者引用编号，例如 `[1]`。编号只能使用 EvidenceBundle 片段前给出的 `reader_citation`，不得创建、改写或猜测编号。不要在正文暴露 `source_id`、`chunk_id`、文件路径或“本报告/上述报告”等过程性表述。
6. 趋势、原因和影响可以在证据基础上综合推导，并明确其依据、适用条件和不确定性。证据只支持局部范围时，收窄结论范围和措辞强度。
7. 生成简洁的章节摘要，供后续章节维持术语和结论一致。摘要不得引入正文及证据之外的新事实。

## Markdown 输出协议

只输出 Markdown，不输出 JSON、代码围栏、写作说明或前后缀解释。使用下列固定结构，标题可随当前章节变化：

```markdown
# 当前章节标题

## 本章摘要

用一段简洁文字说明本章结论。

## 正文

正文中的事实或重要判断使用上下文已分配的数字标记，例如 `[1]`。

## 证据缺口

- 使用 `- [hard] 缺口说明` 标识缺失的关键事实、必需数据、官方规范或关键引用；使用 `- [soft] 缺口说明` 标识可用限制性措辞处理的补充材料。没有缺口时写“无”。
```

`证据缺口`是文档 Agent 向主控交付的内部信息，不会写入读者 Markdown。程序会从 Markdown 提取摘要、数字引用和结构化证据缺口，再仅以标题、摘要、正文和自动生成的“参考来源”构建读者版本。不要自行输出参考来源、`source_id`、`chunk_id`、JSON 字段或文件路径。

## 证据不足与冲突

- 缺少支撑时保留为 `gaps`，不得用模型常识补成确定事实，也不得编造数据、来源、引用或访问结果。
- 来源冲突时说明冲突口径、时间、地区或定义差异；无法解释时保留冲突，不强行得出唯一结论。
- 只有标题、URL 或模糊摘要而无有效正文片段时，不将其作为关键事实的充分证据。
- 当前证据无法满足章节目标时，返回已能完成的内容和具体缺口，供主控决定补充搜索或调整范围。

## 交付前检查

- 章节内容直接回应 `section_goal`，并满足 `evidence_requirements` 与 `writing_constraints`。
- 每项关键事实和重要判断能够回指实际使用的证据标识，引用与相邻主张语义对应。
- 正文数字引用仅使用实际支持该句的 EvidenceBundle 来源编号；同一 URL 的多个片段共享同一个编号。程序据此生成来源级 citation map，并保留该来源的支持性 Chunk 位置。
- 对过期、间接、冲突或范围有限的证据使用了匹配的谨慎表述。
- 与全文大纲及近期已批准章节摘要保持术语和结论一致，未擅自撰写其他章节。
- 交付内容遵循 Markdown 输出协议。章节摘要、实际引用、缺口和质量标记由程序后续解析和组装。
