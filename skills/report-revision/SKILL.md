# 报告章节修订

## 适用范围

仅用于 `document.revise_section`。输入包括任务中的 `base_draft`、对应 `ReviewIssue`、章节标题、`outline_ref`、检索问题和补证后回取的 EvidenceBundle；章节目标、写作约束和近期章节摘要由程序根据 `outline_ref` 及主控上下文解析后提供，不得虚构任务中不存在的字段。修订产物是目标版本的新 Markdown，旧版本必须保持可回放。

`ReviewIssue` 决定本次修改范围，EvidenceBundle 是事实与引用的唯一依据。版本号、Markdown 持久化、差异记录、Token 预算、检索、A2A 生命周期和权限由程序管理。

## 修订方法

1. 先读取 `base_draft` 指向的旧章节，逐项理解审核问题的定位、类型和请求修改。保留未受问题影响且仍与当前证据一致的内容，避免整章无目的重写。
2. 对 `missing_evidence`、`unsupported_claim`、`conflicting_sources` 和 `citation` 问题，优先使用新 EvidenceBundle 中直接相关、可定位的证据；证据仍不足时，收窄或删除无法支持的结论，并在内部“证据缺口”中如实保留。
3. 对 `structure` 与 `style` 问题，调整段落结构、术语、过渡和表达强度，同时保持章节目标、已批准章节摘要和报告整体口径一致。
4. 每项保留或新增的重要事实及判断都使用当前 EvidenceBundle 已分配的读者编号 `[N]`。同一来源的多个 Chunk 使用同一编号；不得沿用旧版本中未出现在当前证据包的编号，不得编造引用。
5. 用本章摘要概括修订后的结论，不引入正文与证据外的新事实。

## Markdown 输出协议

只输出 Markdown，不输出 JSON、代码围栏、修订说明或前后缀解释。输出结构与首稿保持一致：

```markdown
# 当前章节标题

## 本章摘要

修订后的一段章节摘要。

## 正文

修订后的正文，事实和重要判断使用当前证据包分配的 `[N]`。

## 证据缺口

- 使用 `- [hard] 缺口说明` 或 `- [soft] 缺口说明`；没有缺口时写“无”。
```

`证据缺口`只交给主控的结构化成果，不会进入读者 Markdown。程序负责生成来源表、citation map 和版本化 Artifact；不要输出来源表、机器标识、路径、差异记录或任务状态。

## 交付前检查

- 每一项审核问题均已被处理：补充、收窄、改写、保留限制，或以明确缺口说明无法解决的原因。
- 正文没有因为修订降低既有可追溯性；所有 `[N]` 均来自当前 EvidenceBundle 且与相邻主张相关。
- 没有改变当前章节之外的范围，也没有把补证过程、审核意见或“本报告”等过程性语言写入读者正文。
- 新版本能够独立阅读，并与章节目标及当前写作约束一致。
